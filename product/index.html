Accounts and access

Access decisions follow the record across service boundaries.

Daptin signs users in and evaluates guest, user, owner, and group permissions for each table. A customer portal can give every person private records and grant a team access through one workspace group.

Relationship and asset requests evaluate table and row access; action calls use action permissions. A /live system topic checks table-level CanPeek when the client subscribes.

Files and content

Attach files to records. They inherit the record's permissions.

Add an asset column to store a product image with its product, an invoice with its order, or a support attachment with its ticket. The record's access rules determine who can retrieve the file.

Use local storage for a small installation or configure an rclone-backed store for S3-compatible services and other supported providers. Daptin also serves stored files through site and subsite routes.

Actions and scheduled work

Turn multi-step backend work into one API call.

Define an approve order action that validates the request, changes the order status, creates an audit record, and sends a notification. The frontend calls the named action instead of coordinating those steps in the browser.

Run actions through HTTP, GraphQL, or scheduled tasks. Each action declares inputs, validation or conformation, conditions, and ordered outcomes. State tracking records allowed transitions; invoke an action separately when a transition should perform work.

External services

Expose selected provider operations without sending their secrets.

Install an OpenAPI description and expose selected operations as Daptin actions. Store one shared provider credential on the server or keep a separate OAuth token for each signed-in user.

The integration-auth demo verifies that one signed-in user cannot invoke another user's connected-account credential.

Live updates

Each table has a live topic for create, update, and delete events.

Daptin publishes record events through its /live WebSocket endpoint. Subscribe a dashboard to order changes, a customer portal to ticket updates, or a monitoring screen to usage.

A system-topic subscription checks the table's CanPeek permission. Reconnect clients after a membership or permission change so they establish a new subscription.
