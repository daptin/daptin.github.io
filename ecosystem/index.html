CONNECT YOUR APPLICATION

Use plain HTTP or
a client that saves time.

No SDK is required. The CLI and language clients package common work such as signing in, reading related records, running an operation, and uploading a file.

SERVER

docker run -p 127.0.0.1:6336:8080 daptin/daptin:v0.12.36

RUNNABLE DEMOS

See the difficult parts
working end to end.

Each repository answers a practical question: can another app sign in through Daptin, can customer credentials stay isolated, can a quota stop a call, and can an ordinary OpenAI client switch providers?

AI PROVIDERS

Keep the client while changing the provider

Use the official OpenAI SDK for model listing, chat, streaming, completions, and embeddings through Daptin’s /v1 address.

Run the demo ↗ CUSTOMER SIGN-IN

Let another application sign in through Daptin

Register a client and complete an OAuth 2.0 / OpenID Connect authorization-code flow with PKCE, tokens, and user information.

Run the demo ↗ PAID API PLANS

Stop calls at a quota and debit credits

Record API and model use, reject calls when the plan is exhausted, preserve usage history, and charge a credit wallet.

Run the demo ↗ CONNECTED ACCOUNTS

Keep every customer’s credentials separate

Store OAuth tokens and encrypted credentials for each person and verify that one account cannot use another account’s secret.

Run the demo ↗ SEPARATE APPLICATIONS

Use one Daptin server to sign in to another

Run provider and consumer roles on separate instances and follow the complete authorization-code flow between them.
