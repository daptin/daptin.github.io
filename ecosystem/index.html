Ecosystem and compatibility

Connect through documented APIs, protocols, and tools.

Daptin does not require every application and operator to use one proprietary client. Connect directly over JSON:API or GraphQL, automate with the CLI, use focused SDKs, import provider contracts, attach storage, or meet existing software through standard protocols.

  • HTTP-first APIs
  • CLI and SDKs

01 · Application clients

Start with the wire contract; add a client when it saves work.

02 · Operator tools

Discover and operate the live model.

The Daptin CLI discovers resources and actions from a running server, then supports data operations, OAuth setup, integration installation, cloud-store management, and asset workflows. The bundled dashboard provides a visual administrative surface for the same backend.

Discovery routes—including OpenAPI, metadata, and generated JavaScript models—help tools follow the model that is actually running. Treat administrative interfaces as privileged operational surfaces: restrict access, use explicit identities, and test permissions separately from the end-user application.

06 · Selection rule

Choose the least coupled interface that completes the job.

  • Use direct HTTP for portability, small scripts, and clients that already understand JSON:API or GraphQL.
  • Use an SDK when typed helpers and repeated resource/action calls justify another dependency.
  • Use the CLI for discovery, administration, repeatable setup, and operator workflows.
  • Use an imported integration when provider credentials and behavior belong behind a stable backend action.
  • Use a standard protocol when existing tools already speak it—after testing Daptin’s exact protocol scope.
  • Use a runnable demo to verify a complex contract and its denial paths before adapting it.
