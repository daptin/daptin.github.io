Platform architecture

A data model configures the application backend.

Daptin is a self-hosted application server, not a code generator. It loads your schema into a shared resource runtime and keeps the running APIs, permissions, automation, files, integrations, and operational services connected to that model.

  • Declarative model
  • Shared policy pipeline
  • One deployable server

01 · The core

The resource graph is the center of the runtime.

A YAML or JSON schema describes tables, columns, relations, validation, conformation, indexing, and feature flags. At startup Daptin reconciles that definition with a relational database and records each configured resource as world metadata.

Each resource receives standard identity, ownership, timestamps, version, and permission fields. Public requests use indexed UUID references while database relationships can use compact internal keys. The same resource definition drives JSON:API routes, optional GraphQL, discovery documents, actions, realtime topics, and the administrative dashboard.

02 · Request path

Every request passes through the same access checks.

1. Identify the caller

Guest, user, owner, group, and administrative identities establish the context. JWT sessions, OAuth connections, and action identities enter the same authorization model.

2. Bound the request

Rate and active-request controls run before application handlers. Input validation and conformation happen before persistence; database connection pools cap downstream pressure.

3. Authorize the operation

Permissions apply at table, row, relationship, and action levels. Linking a related record requires both its existence and permission to refer to it.

4. Commit and deliver

Core CRUD database effects share a transaction. Successful changes can update audit/state data and produce realtime events; external side effects retain their own delivery guarantees.

05 · ColumnInfo contract

Each column carries storage, interface, and policy metadata.

Name and ColumnName identify the logical and normalized database field; ColumnDescription feeds generated documentation. DataType selects physical storage while ColumnType selects semantic validation, fake data, dashboard representation, OpenAPI shape, and GraphQL type.

Constraint fields cover primary key, auto-increment, index, uniqueness, nullability, and default value. Permission provides field-level access metadata. ExcludeFromApi removes internal fields from public serialization. IsForeignKey plus ForeignKeyData binds a field to a self resource or external namespace such as cloud_store; Options carries typed label/value choices.

Semantic and physical types are separate. A managed image uses a text/blob-compatible DataType, an image/file ColumnType, and an explicit cloud_store binding. ColumnType: image alone is not a complete asset definition.

07 · Deployment boundary

You operate the server and the data around it.

Daptin ships as native release assets and a container. SQLite makes local evaluation simple; PostgreSQL or MySQL fit durable production deployments. Files may stay local or use a configured store. Olric supplies distributed cache, pub/sub, and counters when several instances need shared runtime behavior.

The platform reduces application-specific backend code; it does not remove infrastructure work. Production owners still choose database topology, storage durability, TLS termination, trusted proxies, backups, monitoring, capacity, upgrade strategy, and recovery tests.

Transaction scope: database transactions cover database effects, not remote HTTP calls, SMTP acceptance, or cloud-file operations. Design external work for retries and idempotency.
