Docker Compose

Use the Compose example to learn the connection setup.

The latest release source archive includes a small PostgreSQL Compose example, but it uses moving images, fixed sample credentials, no persistent volumes, and no health check. Treat it as connection-string syntax, not a production manifest. Replace its secrets, record tested image digests, mount database and asset storage, and add health checks before using Compose beyond local evaluation. 

# The latest release archive contains:
docker-compose-examples/daptin-postgres.yml

# Review credentials and persistence before running it.
curl --fail http://127.0.0.1:8090/ping

Kubernetes

Bring a deployment maintained for your cluster.

The latest release source contains historical Kubernetes examples that are not suitable for a current production cluster. They use removed extensions/v1beta1 APIs, embed sample database connection details, and omit persistence, probes, resource requests, security context, and secret management. Do not apply them unchanged.

Build a current Deployment and Service around the latest Daptin image. Supply database credentials through a Secret, use an external durable database, mount or connect shared asset storage, expose /ping only as liveness, and define readiness around required dependencies. Validate concurrent schema startup before running several instances.

Persistence and operations

Back up the database and files as one set.

A Daptin backup is incomplete if it contains only SQL rows. Keep the database, local asset directory or cloud-store data, deployment configuration, and encryption material in the recovery plan. Restore the complete set in a separate environment before an upgrade.

Databases

Use SQLite for local development. Daptin documents MySQL and PostgreSQL for production deployments, with connection strings supplied through flags or environment variables.

Health checks

The latest release exposes /ping for process liveness. Use an external database-aware readiness check before routing traffic. The /health path is the admin application, not a probe.

TLS and logs

Configure certificates and HTTPS in Daptin or terminate TLS at a trusted proxy. Retain process logs and enable audit records for changes that require a history.

Upgrades

Back up and restore-test the database and file store before changing the Daptin image or executable. Test the latest release, record the deployed artifact or image digest, watch its health checks, and keep a tested rollback artifact.
