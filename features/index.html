Daptin feature map

See what you can ship with Daptin.

Most applications need far more than endpoints. Daptin brings the data layer, users, access rules, files, backend work, integrations, live updates, and operational controls into one self-hosted application server.

Choose a capability

Data is only the beginning.

Run identity, permissions, files, business operations, schedules, integrations, realtime clients, collaboration, mail, publishing, AI routing, metering, and operational controls from the same application server.

See how Daptin is engineered →

01

Data and APIs

Data modeling

Define fields, types, validation, defaults, indexes, unique values, translations, and relationships in YAML, JSON, or the administrative interface.

Public IDs without slower joins

Clients use stable UUIDv7 references while Daptin keeps compact integer keys for database relationships.

APIs and discovery

Use JSON:API resources, optional GraphQL, filtering, sorting, pagination, aggregation, OpenAPI, metadata, and generated JavaScript models.

Move data in and out

Import CSV and spreadsheets, export records, create representative sample data, and inspect everything through dashboard3.

02

Users and permissions

Authentication

Run signup, signin, password reset, JWT sessions, OTP verification, and session invalidation after credential changes.

Permissions and tenancy

Control guest, owner, user, and group operations for tables, records, relationships, actions, teams, and workspace boundaries.

OAuth and OIDC provider

Register applications and provide authorization, tokens, user information, introspection, and signing keys.

03

Files and publishing

Files and assets

Attach images, documents, video, and other assets to application records instead of managing disconnected URLs in your frontend.

Cloud storage

Start with local files or configure rclone-backed storage for S3-compatible services and other supported providers.

Streaming and HTTP caching

Serve with access checks, ETags, conditional responses, compression-aware caching, bounded memory reads, and streaming for larger files.

Sites and publishing

Publish managed site directories, render templates, and turn stored records into RSS, Atom, or JSON feeds.

04

Actions and scheduled work

Actions

Define operations with named inputs, validation, conditions, and ordered outcomes, callable through HTTP or GraphQL.

Scheduled work

Execute the same server action later or repeatedly without adding a separate scheduler service.

State tracking

Define valid states and transitions, then retain transition history for application records.

Keep database work together

Core record changes share a transaction so related database writes normally commit together or roll back together.

05

Integrations and AI routing

External API integrations

Import OpenAPI definitions and expose selected provider operations as permission-aware Daptin actions.

Shared or per-user access

Call a provider with one server-stored credential or select the connected OAuth token belonging to the signed-in user.

Use more than REST

Execute supported REST, GraphQL-over-HTTP, unary gRPC, and WebSocket request/response integrations through server-side operations.

AI model gateway

Point OpenAI-compatible clients at Daptin for model discovery, chat completions, legacy completions, streaming, embeddings, tool calls, and provider routing.

06

Realtime and collaboration

Realtime events

Subscribe dashboards and application clients to create, update, and delete notifications through the /live endpoint.

Collaborative documents

Store and relay Yjs updates when several people need to work in the same document experience.

Feeds for readers and tools

Expose selected records through RSS, Atom, and JSON feeds without maintaining another publishing pipeline.

Permission-aware subscriptions

System-topic subscriptions check table access when clients connect, keeping live data within the configured access model.

07

Standard protocols

Application APIs

HTTP and HTTPS, JSON:API, optional GraphQL, OpenAPI discovery, WebSocket, Yjs, and OpenAI-compatible streaming.

Mail server

SMTP delivery, mail accounts and mailboxes, IMAP access, outgoing queues, and retries for temporary mail failures.

File and feed protocols

FTP, FTPS, WebDAV-style routes, RSS, Atom, and JSON Feed connect existing clients to Daptin data.

Identity

OAuth 2.0, OpenID Connect, JWT, PKCE, TOTP, TLS, and ACME-backed certificate workflows.

08

Deployment and operations

Self-host one runtime

Run a native executable or the latest container with SQLite, MySQL, or PostgreSQL and the storage arrangement your application needs.

Metering and quotas

Measure requests and tokens, assign plans, enforce quotas, and run credit hooks for productized APIs.

Operations

Use process liveness, runtime statistics, logs, database-pool information, audit records, traffic controls, and live counters.

Scale shared behavior

Use Olric for distributed cache, PubSub, and shared rate counters when several Daptin instances serve the same application.
