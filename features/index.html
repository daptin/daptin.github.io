Feature reference

What Daptin
provides.

Define tables in YAML or JSON. Daptin creates API routes for their records and applies the same user, group, and row permissions to actions, files, events, and integrations.

01

FOUNDATION

Tables & schema

Define tables, columns, relationships, validation, and indexes in YAML or JSON.

Declarative resources

Load YAML or JSON schemas with tables, columns, indexes, relationships, validation rules, defaults, and behavior flags.

Resource metadata

Daptin adds stable public references, timestamps, versions, and permission metadata to every resource.

Field types

Use fields for text, numbers, dates, JSON, locations, ratings, measurements, files, images, audio, and video.

Database choice

Use SQLite locally or connect Daptin to MySQL, MariaDB, or PostgreSQL.

Relations and joins

Model belongs-to, has-one, has-many, and many-to-many relationships with generated relationship APIs.

Data lifecycle

Import CSV, XLSX, JSON, or YAML; export structured data; generate test records; enable multilingual fields, auditing, state, or metering.

02

DELIVERY

APIs & discovery

Daptin creates JSON:API routes, optional GraphQL, aggregation queries, OpenAPI, and metadata from the configured tables.

JSON:API resources

Create, read, update, and delete records and relationships. Requests support filtering, sorting, pagination, includes, and sparse fields; responses omit records the user cannot read.

Optional GraphQL

Generate queries, mutations, relationships, aggregations, and action execution from the configured model.

Aggregation API

Group, join, filter, sample, order, and calculate count, sum, average, minimum, maximum, first, or last values.

OpenAPI output

Publish an OpenAPI description of resources, actions, integrations, auth requirements, examples, and data features.

Table metadata

Read table and field definitions through metadata routes. Dynamic clients can discover the available records and fields.

Plain HTTP clients

Call the API from web, mobile, server, automation, or agent clients. The JavaScript and Go clients are optional.

Explore the APIs →
03

ACCESS CONTROL

Identity & permissions

Users, groups, ownership, and permission bits control access to records, relationships, actions, topics, and integrations.

Users and groups

Create users and groups, assign memberships, set record owners, and use groups for teams or tenant accounts.

Granular permissions

Gate read, create, update, delete, refer, execute, and peek operations at entity, row, relation, and action levels.

Authentication flows

Support password signup and signin, JWT sessions, reset flows, and TOTP-based two-factor authentication.

OAuth client

Connect to external OAuth providers, complete browser authorization flows, and store linked tokens securely.

OAuth/OIDC provider

Issue, refresh, revoke, and introspect tokens through authorization, JWKS, userinfo, and discovery endpoints.

Multi-tenant patterns

Combine ownership, usergroups, relations, and row permissions to isolate tenant workspaces on one Daptin deployment.

Understand permissions →
04

BACKEND LOGIC

Actions, schedules & state

Define server-side actions, call them through the API, or run them on a cron schedule.

Action definitions

Define an action’s input fields, validation, conditions, ordered steps, response, and whether it requires an existing record.

Action steps

Create or change records, call registered Go functions, render content, download files, set headers or cookies, and run further steps.

Scheduled tasks

Call the same actions on cron schedules under a selected user identity and permission context.

State tracking

Define allowed source-to-destination events, record transitions, versions, and audit history for resource state.

Data exchange

Before or after an action, map fields and copy records to or from a configured external source.

Built-in operations

Handle auth, OAuth, storage, mail, sites, integrations, certificates, publishing, imports, exports, and administration.

Current scope: state tracking records allowed transitions. Hierarchical states, parallel branches, and implicit entry or exit actions are outside its scope.

Build with actions →
05

CONTENT

Files, storage & sites

Attach files to records, store them locally or through rclone, and serve websites by host name or path.

Asset columns

Attach images, video, audio, documents, or other blobs to records with dedicated retrieval and upload routes.

Cloud stores

Connect local or rclone-backed storage providers using encrypted credentials and resource-managed configuration.

Upload workflows

Support direct, multipart, and presigned-style operations where the configured storage provider allows them.

HTTP caching

Serve files with ETags, cache headers, gzip, in-memory caches, negative caching, and optimized filesystem paths.

Subsites

Route sites by host or path, sync content from storage, apply basic auth, and serve multiple frontends from Daptin.

Go templates

Render resource data into hosted pages with template hooks while retaining the same storage and routing layer.

Explore storage and assets →
06

CONNECTIONS

Realtime & protocols

Enable WebSockets, feeds, YJS, SMTP, IMAP, FTP, or WebDAV-style routes from the Daptin process.

Resource events

Publish create, update, and delete events through a bounded worker pool and Olric-backed PubSub.

WebSockets

Subscribe to permission-aware table and topic updates through the structured /live message protocol.

YJS collaboration

Enable YJS endpoints on selected columns for collaborative document editing.

Feeds and streams

Expose selected data through stream definitions and RSS, Atom, or JSON-style feed routes.

Mail and files

Enable database-backed SMTP, IMAP, FTP, and FTPS services alongside the HTTP application server.

WebDAV-style routes

Enable CalDAV/CardDAV routes for basic file-oriented storage and discovery where that limited scope is sufficient.

Current scope: CalDAV/CardDAV routes provide basic WebDAV-style file storage. Full calendar and contact protocol compatibility is outside their current scope.

07

CONNECTIVITY

Integrations & LLM routing

Import external APIs and route model requests through credentials stored and resolved by Daptin.

OpenAPI imports

Install OpenAPI v2 or v3 operations and expose provider-scoped discovery and execution routes.

Multiple transports

Connect REST, GraphQL, short-lived WebSocket, and unary gRPC operations through one integration model.

Stored credentials

Daptin loads OAuth tokens or encrypted credentials when it calls an integration. Callers submit operation fields and do not receive the stored secret.

OpenAI-compatible API

Serve chat completions, streaming chat, completions, embeddings, models, and tool-call-compatible payloads under /v1.

Provider routing

Map model names to configured providers and credentials. Clients send requests to Daptin’s /v1 routes.

OpenAPI listing

Daptin adds installed provider operations to its OpenAPI document.

Explore integrations →
08

OPERATIONS

Metering, caching & health

Configure usage plans and quotas, inspect health and statistics, and coordinate caches and events across instances.

Plans and quotas

Define plans, memberships, request and compute limits, pricing metadata, overages, and period quotas.

Usage metering

Record CRUD, action, and LLM usage, including token dimensions, and invoke post-metering credit hooks.

Rate limits

Apply API limits with clustered Olric counters and reject requests before recording usage when hard quotas fail.

Cache and PubSub

Use embedded Olric, LRU or file caches, event queues, and distributed PubSub across Daptin instances.

Health and visibility

Expose liveness, readiness, statistics, configuration, logs, profiles, metadata, and optional audit records.

Startup and shutdown

Daptin reports listener and TLS errors during startup. On shutdown, it drains HTTP and protocol sessions, flushes events, and then closes the database.

09

DEVELOPER EXPERIENCE

CLI, clients & starting points

Use the raw API everywhere, then add focused tools where discovery, typing, or common workflows save time.

Self-describing CLI

Discover resources and action requirements, manage contexts, authenticate, traverse relations, and operate integrations, OAuth, storage, and assets.

JavaScript & TypeScript

Use typed entities, JSON:API, action calls, authentication, asset URLs, and direct or multipart storage uploads.

Go client

Connect native Go applications to Daptin resources and backend action APIs.

Distribution choices

Install the CLI through Homebrew, Scoop, Go, Linux packages, or downloadable binaries; run the server through Docker or a release binary.

Reusable schemas

Start from resource packages for blogs, FAQs, stores, payments, construction projects, transactions, styles, and todos.

Runnable demos

Run repositories for LLM compatibility, OAuth/OIDC flows, credential isolation, metering, quotas, and credit accounting.
