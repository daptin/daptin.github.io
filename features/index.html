01

APPLICATION DATA

Model the records your product runs on

Describe products, orders, customers, tickets, invoices, or any other records and how they relate.

Shape data around the product

Define fields, relationships, validation, defaults, and indexes in YAML or JSON. Daptin creates the database structure and keeps the model available to clients.

Bring existing records with you

Import CSV, spreadsheets, JSON, or YAML and export records when another team or system needs them. Generate test records while building a new screen.

Start locally, choose the database you need

Run with SQLite for a quick local setup, or connect Daptin to MySQL, MariaDB, or PostgreSQL for a deployed application.

02

CLIENT APIS

Give every screen a usable data API

Your web, mobile, or internal app can list, search, create, and update records as soon as the model is loaded.

Build list, detail, and edit screens

JSON:API routes cover records and relationships with filtering, sorting, pagination, includes, and field selection. Results already respect the signed-in user’s permissions.

Answer dashboard questions

Group and join records, then calculate counts, totals, averages, minimums, and maximums without adding a separate reporting endpoint.

Let clients discover the backend

OpenAPI and metadata describe the running tables, fields, actions, and authentication. Enable GraphQL when a client is better served by queries and mutations.

Explore the APIs →
03

ACCOUNTS AND TEAMS

Give customers private accounts and shared workspaces

Protect each customer’s data, let teams work together, and use the same access rules throughout the application.

Handle sign-up and sign-in

Use password accounts, JWT sessions, password resets, and TOTP two-factor authentication instead of building those flows around every new product.

Separate customers and teams

Use ownership, groups, relationships, and row permissions so people see the records for their account or workspace—not somebody else’s.

Connect identity in either direction

Let users sign in through an external OAuth provider, or let another application use Daptin as its OAuth/OIDC provider. Daptin stores external tokens in encrypted credential records.

Read the permissions guide →
04

BUSINESS OPERATIONS

Turn a complete operation into one API call

Give the frontend a single endpoint for work such as approving an order, importing a catalog, sending a receipt, or closing a ticket.

Run the whole operation on the server

Validate input, check conditions, update records, call a registered function, render content, download a file, or set the response in an ordered action.

Repeat work on a schedule

Run the same actions on cron schedules for reminders, imports, clean-up, publishing, or other recurring work, under a selected user’s permissions.

Prevent invalid status changes

Define which simple transitions are allowed—such as draft to approved—and reject attempts to skip the process. Versions and audit records show what changed.

Move data at the right moment

Before or after an action, map fields and copy records to or from an external source—for example, importing a customer before creating an invoice.

05

FILES AND CONTENT

Keep uploads with the records they belong to

A product image stays with its product, an invoice with its order, and an attachment with its ticket.

Add files to real application records

Upload images, video, audio, documents, and other files through routes tied to the same records and access rules as the rest of the product.

Choose where the bytes live

Store files on the local filesystem or connect an rclone-supported service. Clients keep the same Daptin routes when the storage location changes.

Publish and deliver content

Serve files with browser caching, render records into HTML with Go templates, and host multiple small sites by domain or path.

Explore storage and assets →
06

LIVE EXPERIENCES

Let people see changes without refreshing

Update dashboards and shared workspaces when the underlying records change.

Keep dashboards current

Publish record creation, updates, and deletion over WebSockets. Subscriptions use the same read permissions as ordinary API requests.

Build collaborative documents

Enable YJS on selected document fields when several people need to edit the same content together.

Publish updates outside the app

Turn selected data into RSS, Atom, or JSON feeds. Optional mail and file-transfer services can expose records through tools a team already uses.

Explore events and protocols →
07

EXTERNAL APIS AND AI

Connect providers without exposing their credentials

Put external services behind your own authenticated API, whether each customer connects an account or the whole product shares one.

Turn an API description into callable operations

Import an OpenAPI document and call its operations through Daptin instead of writing a new proxy for every REST, GraphQL, WebSocket, or unary gRPC service.

Protect each user’s external account

Store OAuth tokens or custom credentials in encrypted records. Daptin loads the right credential for the call without returning the secret to the client.

Give clients one address for AI models

Route OpenAI-compatible chat, streaming, completion, embedding, and model-list requests to configured providers while keeping provider credentials on the server.

Explore integrations →
08

PLANS AND OPERATIONS

Offer plans, enforce limits, and run the server

Keep usage rules beside the APIs they govern and expose the health information your deployment needs.

Turn API access into plans

Assign users to plans with request or compute limits, prices, billing periods, overage rules, and quotas. Reject calls when a configured limit is reached.

Record usage and charge credits

Meter data, action, and LLM calls—including input and output tokens—and run an action after the call to debit credits or update billing records.

Deploy and observe

Use liveness, readiness, statistics, logs, profiles, metadata, and optional audit records. Multiple instances can share events, caches, usage counters, and rate limits through Olric.
