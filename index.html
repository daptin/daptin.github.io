Schema to running product

Add a product table.
Daptin creates its API.

Daptin reads the model at startup and creates the table, relationships, API routes, and admin view. Your frontend calls the generated API; it does not need to reproduce the data rules.

Four application jobs

Build the frontend.
Configure the backend.

Use Daptin for a complete backend or for one service that the current application lacks.

01

Build a customer portal

Model customers, workspaces, projects, and tickets. Daptin supplies accounts, group membership, private records, files, and API actions.

See the portal model →
02

Run internal operations

Import orders, update records, approve exceptions, and run scheduled work. Staff use dashboard3 or a purpose-built frontend.

See the operations model →
03

Manage content and files

Keep a product photo with its product, an invoice with its order, or a document with its workspace. Record permissions decide who can download it.

See the content model →
04

Offer an authenticated API

Put provider credentials on the server, meter API or model use, reject calls at a quota, and keep the usage record.

See the API service model →

One permission model

Remove a person from a workspace.

That person loses access to the workspace records, related downloads, allowed actions, and live record events. Daptin checks the same ownership and group rules at each entry point.
