Server-side controls

Authentication, execution, and runtime state stay observable.

Handle reused credentials, interrupted multi-step work, and process health on the server.

Credentials

Provider secrets stay on the server, not in browser code.

An integration uses a shared credential or the signed-in user's encrypted OAuth token. The caller supplies input, not the secret.

Configure an integration →
Authentication

Single-use codes, token rotation, and replay protection.

OAuth codes are single-use, refresh tokens rotate, provider PKCE is required, and OTP attempts are cluster-shared.

Read the token lifecycle →
Operations

Health checks, statistics, audits, and live counters.

/ping reports process liveness; /statistics exposes web, database-pool, host, and resource state. Logs, audit tables, caching, distributed PubSub, and rate counters are built in.
