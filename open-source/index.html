Use the machine you already have

Native releases cover Windows x86-64, Linux x86-64, Linux ARM64, and macOS Intel. Linux ARM64 runs on 64-bit Raspberry Pi systems. Docker, Compose, and Kubernetes files are included.

Avoid a required client SDK

Web, mobile, server, automation, and agent clients can use documented HTTP APIs. JavaScript, TypeScript, Go, and CLI clients are available when they make the work easier.

LOCAL INSTALLATION

Run the current release locally.

$ docker run --rm -p 127.0.0.1:6336:8080 daptin/daptin:v0.12.36

Open localhost:6336 and create the first administrator. This command stores records and files inside the temporary container; use persistent storage and an external database for production.

THE SELF-HOSTING TRADE-OFF

You control production.
You also operate it.

Daptin reduces the application services you have to build. It does not remove the work of running a reliable database, storage, network, and server.

What Daptin gives the product team

  • Data APIs, customer accounts, permissions, uploads, operations, live updates, and integrations
  • A choice of common SQL databases and file-storage locations
  • Source code, issue history, and versioned releases you can inspect
  • Portable YAML or JSON application definitions
  • Optional GraphQL, mail, FTP, and other services
  • Health, statistics, audit, cache, and TLS controls for deployment

What production still requires

  • Database backups and tested restores
  • Stable JWT and encryption secrets
  • HTTPS, DNS, and certificate operations
  • Durable storage and capacity planning
  • Monitoring, alerting, and log retention
  • Upgrade, security, and incident processes
A PRACTICAL DEPLOYMENT PATH

Prove the model locally.
Harden it for production.

  1. STEP 1

    Build on one machine

    Use one binary, SQLite, and local files while creating the model and frontend.

  2. STEP 2

    Add durable services

    Move to PostgreSQL or MySQL, persistent storage, HTTPS, backups, secrets, and monitoring.

  3. STEP 3

    Add instances when required

    Share the database and use Olric for cache entries, live events, usage counters, and rate limits.
